# 任务看板 · WorkBuddy Task Board

把电脑上 WorkBuddy 的任务状态与**完整对话**同步到一个只属于你的手机看板。电脑关机、App 关闭，依然能翻看历史。

> 一个自托管的小工具：不加好友、不上传第三方服务，数据放在**你自己的** WorkBuddy 云应用里。

## 它能做什么

- **任务列表**：标题、状态、工作区、模型、消息数，按今天 / 昨天 / 本周分组
- **完整对话**：点开任意任务，按桌面端样式渲染——头像、气泡、时间戳、代码块、表格、列表
- **右侧导航**：阅读时右侧常驻三段折叠面板——对话列表（切任务）、消息目录（跳到某轮提问）、文件（看产物内容）
- **文件可直接查看**：图片、文本、音频在手机上点开即看，其他类型可下载；单文件上限 4 MB
- **手机可安装**：添加到主屏幕后全屏运行，有独立图标，和原生 App 观感一致
- **关机可查**：云端持有最后一份快照，与电脑是否通电无关
- **搜索**：按标题、工作区、摘要过滤
- **退出自动补传**：关闭 WorkBuddy 后最迟 2 分钟自动同步一次（可选，`install.sh --auto`；守卫脚本在 App 运行期间立即退出，无常驻进程）

## 右侧导航

阅读一段长对话时，往往想切到另一段、跳到某一轮、或看看这次生成了什么文件。这三件事都放在右侧一列里，不额外占一屏。

| 维度 | 定义 |
|---|---|
| **位置** | 详情面板内的右侧一列（宽屏 ≥900px 常驻，272px）；窄屏收起为右上角「☰ 导航」按钮，点开后从右侧滑入 |
| **结构** | 三段纵向堆叠：对话列表 / 消息目录 / 文件。同一时刻只展开一段，展开的那段占满剩余高度并独立滚动，段头显示条目数 |
| **对话列表** | 全部任务，按「今天 / 昨天 / 本周 / 本月 / 更早」分组；当前项浅蓝底、`aria-current="true"`，不在视野内会自动滚入 |
| **消息目录** | 当前任务内的每一轮提问：序号 + 首行文本（两行截断）+ 时间；点击后滚到该条并短暂高亮 |
| **文件** | 该任务已同步的产物文件：扩展名徽标 + 文件名 + 大小；点击打开预览（图片 `<img>`、文本 `<pre>`、音频 `<audio>`，其余提供下载） |
| **选中行为** | 切任务 → 高亮转移、详情复位、加载对话与文件；跳消息 → 滚动定位 + 1.4 秒高亮；开文件 → 弹出预览层（Esc 或点遮罩关闭） |
| **与主列表的关系** | 对话列表与主列表同源同序，但不受搜索与筛选影响——避免「过滤后找不到刚看的那条」 |

**关闭按钮**位于面板右上角，固定悬浮、不随内容滚动，长对话滚到任何位置都能一次关闭；宽屏时会自动让到内容列右上角，不压住导航列。

## 文件同步

产物文件（`~/.workbuddy/artifact-index` 指向的本地文件）会随任务一起同步到云端，手机点开即可查看。

- **体积上限**：单文件 4 MB，单次运行总量 80 MB；超限的文件只同步元数据，不同步内容。
- **增量**：按 `mtime + 大小 + 归属` 缓存，未变化的文件不重传；重复点击同步不会重复写入。
- **存哪里**：数据库表 `wb_file`（base64 文本），按 `owner_id` 行级隔离。之所以不用对象存储，是因为云存储只对已登录用户开放写入，而采集端是「匿名 + 设备令牌」，拿不到会话；文件总量又很小（实测 52 个文件 1.6 MB），放数据库更简单。
- **不上传什么**：完整本地路径（只存文件名）、以及超过 4 MB 的文件内容。

## 它不做什么

- **不实时**：只有你点击「任务同步」按钮时才上传一次。这是刻意的取舍——没有后台进程，也就没有常驻耗电
- **不跨平台采集**：同步脚本只读本机 `~/.workbuddy`，仅支持 macOS
- **不是通用任务管理器**：没有数据源它就没有内容

## 架构

```
┌─────────────────────────────────────────────┐
│  Mac                                        │
│  ~/.workbuddy/workbuddy.db  ← 只读           │
│  ~/.workbuddy/projects/*.jsonl ← 只读        │
│              ↓                              │
│  ~/.wb-sync/sync.py   点按钮时执行一次        │
│              ↓ HTTPS                        │
└─────────────────────────────────────────────┘
               ↓ 匿名身份 + 设备令牌（只写不可读）
┌─────────────────────────────────────────────┐
│  WorkBuddy 云应用（你自己的）                 │
│  wb_host / wb_task + RLS + 三个函数           │
└─────────────────────────────────────────────┘
               ↓ 已登录身份 + RLS 按 owner_id 过滤
┌─────────────────────────────────────────────┐
│  手机 PWA                                    │
└─────────────────────────────────────────────┘
```

读路径与写路径完全分离：电脑端用的是设备令牌（**读不到任何历史**，泄露也只能伪造数据，删行即吊销）；手机端用的是登录会话，行级安全按账号隔离。

## 快速开始

前置：本机装有 WorkBuddy 桌面端，并能使用其云服务（用来托管只读副本）。

### 1. 创建云应用

在 WorkBuddy 中创建一个云数据库应用，记下两个值：**应用地址**（形如 `https://xxx.app.workbuddy.host`）与 **publishable key**（形如 `wbpk_...`）。

### 2. 建表与函数

在云应用的 SQL 控制台按顺序执行：

```
sql/01-schema.sql
sql/02-functions.sql
sql/03-policies.sql
```

### 3. 登记你的电脑

生成三个随机值并填入 `sql/04-bootstrap-host.sql` 后执行：

```bash
uuidgen                                                  # host_id
openssl rand -hex 24                                     # 设备令牌
LC_ALL=C tr -dc 'A-Z2-9' </dev/urandom | head -c 10      # 一次性绑定码
```

### 4. 部署前端

把 `web/config.example.js` 复制为 `web/config.js`，填入 publishable key：

```js
window.WB_CONFIG = { publishableKey: 'wbpk_你的值' };
```

然后把这个 `web/` 目录作为静态站点发布（任意静态托管均可）。

### 5. 安装同步按钮

```bash
WB_ENDPOINT=https://你的应用地址 \
WB_PUBLISHABLE_KEY=wbpk_你的值 \
WB_INGEST_TOKEN=第 3 步的设备令牌 \
bash sync/install.sh          # 加 --auto 可启用「退出后自动补传」
```

读 `~/.workbuddy` 需要授权：首次运行如提示权限不足，到「系统设置 → 隐私与安全性 → 完全磁盘访问」里给「终端」或该 App 打开开关。

### 6. 手机端

打开站点链接 → 用同一个 WorkBuddy 账号登录 → 输入第 3 步的绑定码 → 添加到主屏幕。

之后每次想更新数据，点一下程序坞里的 **任务同步** 图标。

## 安全模型

| 层 | 机制 | 作用 |
|---|---|---|
| 身份 | WorkBuddy 账号 OAuth（PKCE）+ 邮箱验证码备用 | 凭证不经过本站 |
| 数据隔离 | 服务端 RLS：`owner_id = auth.uid()` 且排除 `''`、`'anon'` | 陌生人登录成功也读不到任何行 |
| 设备绑定 | 10 位一次性绑定码（只存 md5，用完即失效） | 只有能物理接触这台电脑的人能认领数据 |
| 写入凭证 | 48 位设备令牌（只存 md5） | 只做 upsert，无任何读取通路 |

踩过的一个真实坑：未登录时 `auth.uid()` 返回字面量 `'anon'` 而非 `NULL`，若不显式排除，匿名者可借绑定函数把主机认领到 `'anon'` 名下。已在 `wb_bind` 中拦截。

## 数据边界

**上传**：任务标题、状态、工作区**末级目录名**、模型、消息数、完整对话正文（已剥离注入的系统提示）。

**不上传**：完整文件路径、工具调用参数、剪贴板图片、文件内容、账号密码、任何其他本地文件。

## 已知限制

1. **关机期间新产生的任务采集不到**——采集器只能在主机关机前读取本地库。这是方案的物理上限。
2. **静态资源受分享码保护**——托管平台给每条路径都加了 `?sharecode=` 校验，未带码一律 403。因此**无法提供离线外壳**：Service Worker 想缓存页面就必须把分享码写进脚本，那等于把访问控制公开，不可接受。
3. **前端目前只读一台主机**——数据库层已支持多主机（`wb_host` 多行），前端 `loadData()` 取了 `limit(1)`。有多台电脑需自行扩展。
4. **无推送通知**，需主动打开查看。
